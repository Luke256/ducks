# Ducks
traP 工大祭用 ツール群

- `frontend`: Vue 3 + TypeScript + Vite。イベント・ポスター・物販・売上管理。
- `backend`: Go / Echo。既存の `/api/v1` APIを使用。

backend の日時は、DB 保存・内部処理を UTC（+00:00）に統一し、API レスポンスを返すときに JST（+09:00）へ変換します。対象は売上の `created_at` と来客数の `bucket_start` です。同じ瞬間を保ったまま、タイムゾーンの表現を変換します。

フロントエンドの起動・環境変数・本番配信については [frontend/README.md](frontend/README.md) を参照してください。

## ポスター画像API

- `POST /api/v1/posters`: multipart形式で `festival_id`、`name`、`description` と、同じ `image` フィールドに1〜10枚のファイルを送信します。
- `PUT /api/v1/posters/:id`: 名前・設置場所の編集APIです。
- `PATCH /api/v1/posters/:id/images`: multipart形式で、追加ファイルを `image`、削除対象の画像IDを `delete_image_ids` に指定します。どちらも同じフィールド名を繰り返して複数指定できます。成功時は変更後の画像一覧を返します。

削除指定がない既存画像は保持します。追加と削除を同時に指定すると差し替えになります。編集後も1枚以上が必須で、0枚になる変更は400で拒否し、既存画像を保持します。全画像を削除対象に指定しても、新画像を追加して1枚以上残る差し替えは可能です。削除IDは対象ポスターに属する必要があり、重複指定はエラーです。変更後の上限は10枚、1ファイルの上限は10MiB、リクエスト全体の上限は101MiBです。枚数・削除対象の不正は400、サイズ超過は413を返します。

ポスターのレスポンスでは `image_url` を廃止し、`image` に画像IDとURLを返します。画像がない場合は空配列です。

```json
{
  "image": [
    { "id": "019abcde-0000-7000-8000-000000000001.webp", "url": "/api/v1/images/019abcde-0000-7000-8000-000000000001.webp" }
  ]
}
```

画像レコードの追加・削除はDBトランザクションで反映します。アップロードやDB更新に失敗すると新規ファイルを削除し、既存画像を保持します。旧ファイルはDB更新後に削除します。ファイル削除の失敗はログに残り、自動再試行は行いません。
